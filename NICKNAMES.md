# Уникальные никнеймы

Новый пользователь подтверждает почту кодом, затем выбирает никнейм. Сессия выдаётся только после успешного закрепления ника. Никнейм обязателен, уникален без учёта регистра и неизменяем: 3–24 символа a–z, 0–9 и _, первый символ — буква. В профиле он показан как @nickname.

У существующих пользователей остаются их аккаунты, списки и сессии. Им предлагается один раз закрепить ник: прежнее поле name подставляется в форму как предложение, но не резервируется автоматически, поскольку ранее уникальность не проверялась. Если предложение не соответствует формату или уже занято, нужен другой ник. После закрепления редактирования нет. Повтор того же запроса безопасен, другой ник получает 409.

Внутренний UUID остаётся ключом связей и данных; nickname — уникальный публичный идентификатор. Индекс nickname → userId и запись пользователя обновляются атомарно (Lua в Redis, очередь файлового хранилища). Обычное обновление пользователя не может перезаписать закреплённый ник.

Поиск работает по полному никнейму для вошедших пользователей, ограничен по частоте и возвращает только ник и ссылку на открытый вишлист. Почта, внутренние данные, закрытые списки и данные бронирования в поиск не попадают. Список друзей и заявки в друзья не добавлялись.

Ручная миграция базы не требуется. Индекс создаётся при явном выборе ника. Старые записи name не перезаписываются до подтверждения пользователем.

Проверки: TypeScript, production-сборка, ESLint и 14 автоматических проверок. В локальном браузере проверен путь почта → код → ник → профиль → поиск; письма перехватывались локальным тестовым шлюзом, настоящие письма не отправлялись.
