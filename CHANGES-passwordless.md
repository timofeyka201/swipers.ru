# Вход по коду и исправления аудита

Вход и регистрация объединены: почта → шестизначный код → вход. Код действует 10 минут, допускает пять неверных попыток и используется один раз. Ограничения отправки общие для всех процессов при Redis. Старые маршруты паролей/ссылок возвращают 410. Для отправки нужны RESEND_API_KEY и MAIL_FROM с подтверждённым доменом. APP_URL в production обязателен и должен начинаться с https://.

От человека запрашиваются только почта и необязательный никнейм. Поля имени, фамилии, телефона и мерок удалены из интерфейса; старые значения очищаются при загрузке локального состояния и не возвращаются через API синхронизации. Избранное, корзина, рекомендации и история товаров сохранены. Переход между аккаунтами больше не переносит их данные друг другу.

## Перед обновлением сервера

1. Сделать резервную копию текущего хранилища, ограничив доступ к ней. Остановить запись приложения на время миграции.
2. С теми же переменными окружения выполнить `npm run migrate:passwordless`. Скрипт удаляет старые хэши паролей, токены старых ссылок, телефон, реальные имена из дополнительного профиля и мерки. Текущее поле name аккаунта трактуется как никнейм. Проверить резервные копии отдельно: миграция их не изменяет.
3. Проверить APP_URL, MAIL_FROM, RESEND_API_KEY. На serverless требуется Redis; ошибочная конфигурация больше не переключается молча в файл.
4. Обновить nginx: доверенный внешний прокси должен перезаписывать X-Real-IP и X-Forwarded-For. Подключить HTTPS, если его ещё нет. Ограничить sudo служебного пользователя правом перезапуска swiper.
5. Обновить механизм выкладки из deploy/cloud-init.yaml. Для существующего сервера cloud-init сам повторно не применяется. Новый механизм собирает отдельный релиз и переключает ссылку только после сборки; старый каталог app нужно один раз перенести в releases и заменить ссылкой. Проверить откат на стенде.

## Исправления

- Один безопасный сетевой загрузчик: проверка адресов и redirects, привязка соединения к проверенному IP, общий таймаут и потоковый предел байтов.
- Атомарный CAS в Redis; изменения владельца вишлиста объединяются с актуальными бронями; параллельное создание списка больше не меняет его код.
- Файловая база записывается через уникальный временный файл и rename. Ошибки чтения не превращаются в пустую базу. Этот режим рассчитан на один процесс.
- Синхронизация использует ревизии; старый запрос получает 409. В интерфейсе показывается ошибка сохранения. Успешные ответы старого аккаунта не применяются к новому.
- Старые сессии без issuedAt отзываются после смены пароля; одноразовые токены Redis читаются атомарно.
- Постбэки поддерживают query, JSON и form-urlencoded; ошибка записи возвращает 503. Статистика использует последнее состояние заказа/позиции, отмена исключает его из суммы.
- Ограничены тело JSON и объём событий; поиск не сохраняет идентификатор сессии; добавлены общие лимиты событий.
- Исправлен адрес репозитория в развёртывании, ограничены sudo-права, добавлена блокировка выкладки и возврат предыдущего релиза при неудачной проверке.
- Кэш PWA исключает навигации с query-токенами и приватные страницы; версия кэша повышена.
- Диалоги переводят/удерживают/возвращают фокус. Добавлены CI, линтинг и автоматические проверки безопасности и целостности данных.

## Что требует проверки в инфраструктуре

Реальные письма и доставка кода, Redis с поддержкой EVAL и GETDEL, HTTPS, миграция существующей базы, восстановление резервной копии и обновлённая выкладка. Из этой рабочей копии production не обновлялся. Не проверялись реальные заказы партнёрского провайдера и его политика повторов. Файловое хранение не предназначено для нескольких экземпляров. Удаление старых фото из диска/резервных копий требует отдельной политики хранения.
