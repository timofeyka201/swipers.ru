# Swiper

Мобильная витрина товаров: свайпы, рекомендации, сохранённые товары, «Куплю» и вишлисты с бронированием подарков. Покупка оформляется на стороне магазина.

## Запуск

Node.js 22+, npm. Выполните npm ci, затем npm run dev. Production: npm run build и npm start. Проверки: npm run lint, npm run typecheck, npm test.

## Вход и профиль

Вход и регистрация объединены: почта → шестизначный код из письма. Пароля нет. Код действует 10 минут, пять неверных попыток аннулируют его. При регистрации обязателен уникальный никнейм (без учёта регистра). После выбора его нельзя изменить; друзья находятся по точному никнейму. Имя, фамилия, телефон и мерки больше не запрашиваются. Сохранённое, «Куплю» и история товаров остаются данными сервиса.

Для писем задайте RESEND_API_KEY и MAIL_FROM с подтверждённым доменом. На production требуется APP_URL=https://ваш-домен. RESEND_BASE можно переопределить для тестового почтового шлюза. Без настроенной доставки вход работать не будет; коды не возвращаются в HTTP-ответах.

## Интерфейс

Навигация находится в шапках. В «Сохранённом» три вкладки: «Понравилось», «Куплю», «Вишлист». Гость может собирать желания локально; после входа список переносится в аккаунт. Для публикации и бронирования нужен вход. Владелец не получает сведения о бронях.

Фотографии листаются нажатием на левую/правую половину или стрелками; в открытой карточке работают горизонтальный жест и клавиши ←/→. Подробности открываются по названию. Перетаскивание карточки в ленте — отдельное действие: влево отказ, вправо сохранение, вверх переход к продавцу. Отмена сохраняет ранее отложенные товары.

Цена в интерфейсе и диапазон поиска — в рублях. Переход к продавцу сохраняет товар в «Куплю»; отметка «Заказано» ставится пользователем и не отражает статус доставки. Предпочтения меняются в «Мой вкус». Размеры и игровая механика отсутствуют.

Обновление не требует новых переменных окружения или миграции серверных данных. Локальный формат v6 сохраняет списки и профиль, пересобирает колоду и сбрасывает прежние фильтры, заданные в валюте источника.

## Хранение

AUTH_REDIS_URL и AUTH_REDIS_TOKEN — Redis REST с поддержкой EVAL и GETDEL. Поддерживаются также UPSTASH_REDIS_REST_URL/TOKEN. На serverless Redis обязателен. Для одного процесса на собственном сервере допустим AUTH_FILE=/var/lib/swiper/auth.json. При нескольких экземплярах нужен Redis. Файл хранится вне каталога выкладки, записывается атомарно; его нужно резервировать.

Для перехода со старой версии см. CHANGES-passwordless.md. Миграция npm run migrate:passwordless выполняется один раз с окружением приложения и остановленной записью после резервного копирования.

## Каталог и партнёрка

Лента читает локальный снапшот AliExpress, каждый свайп не обращается к партнёрскому API. Импорт: npm run catalog:ae; изображения: npm run catalog:images. Пути CATALOG_FILE, IMAGE_DIR и AUTH_FILE должны вести в постоянный каталог данных. Остальные настройки перечислены в .env.example. Встроенный data/catalog.json служит запасным снимком, а не источником актуальных цен.

Покупки идут через /api/go/:id. Для уведомлений о заказах задайте AE_POSTBACK_SECRET. /api/ae/postback принимает query-параметры, JSON и form-urlencoded. METRICS_EMAILS или METRICS_KEY ограничивают статистику. При повторных уведомлениях используется последнее состояние заказа/товара; точный формат статусов нужно сверить с провайдером.

## Безопасность и развёртывание

Внешние картинки и предпросмотры загружаются через общий безопасный загрузчик с проверкой адреса, перенаправлений и ограничением объёма. На внешнем доверенном nginx обязательно перезаписывать X-Real-IP и X-Forwarded-For адресом клиента. Закройте прямой внешний доступ к Node и включите HTTPS до приёма реальных входов.

deploy/cloud-init.yaml — шаблон нового Ubuntu-сервера. У существующего сервера он сам повторно не применяется. Выкладка собирает отдельный release-каталог, затем переключает ссылку app и проверяет /api/health. Старый app-каталог нужно один раз преобразовать в ссылку по инструкции CHANGES-passwordless.md. Новая сборка при ошибке не изменяет текущий релиз.

PWA сохраняет публичную оболочку и картинки для работы без сети. Авторизация, синхронизация, приватные страницы и URL с query-параметрами не кэшируются как навигации.

Автоматические проверки находятся в tests/security.test.cjs и .github/workflows/check.yml. Тесты используют отдельное временное хранилище и подменённую отправку писем; реальную почту и Redis следует проверить на стенде.
